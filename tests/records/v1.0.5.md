# 驗證記錄 — v1.0.5

- **日期**：2026-09-07
- **版號**：1.0.5（package.json + src/manifest.json 同步）

## 需求描述

1. 各 LLM Provider 的 API Key 需獨立配置區塊，不可在 Gemini 情境下誤配 OpenCode 的 Key。
2. 非自訂 Provider 的 API Base URL 依官方開發手冊內建配置，僅「自訂」需填寫端點；各 Key 欄位說明須標註實際使用的官方端點。
3. 顯示名稱統一為「OpenCode」（不再使用「OpenCode Zen」）。

## 變更摘要

- `src/index.ts`：
  - 設定區塊重組為五個獨立 Section：
    - `Note AI`（主區塊）：LLM Provider 下拉、System Prompt、Temperature、Top-P
    - `Note AI - 自訂（OpenAI 相容）`：API Base URL、API Key、Model
    - `Note AI - Gemini`：Gemini API Key
    - `Note AI - DeepSeek`：DeepSeek API Key
    - `Note AI - OpenCode`：OpenCode API Key
  - 各 Key 欄位說明加註官方端點（自動使用）：
    - Gemini：`https://generativelanguage.googleapis.com/v1beta/openai`（ai.google.dev/gemini-api/docs/openai）
    - DeepSeek：`https://api.deepseek.com`（api-docs.deepseek.com）
    - OpenCode：`https://opencode.ai/zen/v1`（opencode.ai/docs/zen）
  - 名稱：Provider 選項、Key 欄位標籤、keyLabel、區塊名稱全部改為「OpenCode」。
  - 缺 Key 錯誤訊息改為指向對應區塊：「請先在設定 → 「Note AI - ○○」區塊中填入 API Key」。
- `resolveLLMConfig()` 邏輯不變：Provider → 讀取對應欄位之 Key（隔離由 UI 區塊 + 欄位映射雙重保證）。

# 驗證記錄 — v1.0.6

- **日期**：2026-09-07
- **版號**：1.0.6（package.json + src/manifest.json + publish/*.jpl 內嵌版號，三者一致）

## 需求描述

1. 設定改回**單一區塊**，透過 ComboBox（Provider 下拉選單）區分不同可配置的內容：API Key 欄位內容隨 Provider 切換自動載入/存回，各供應商金鑰內部獨立保存。
2. 版號必須與 commit / 產物一致，並將此條件寫入開發規範（AGENTS.md）。根因：v1.0.5 原始碼已遞增版號，但 .jpl 建置於遞增之前，Joplin 顯示舊版號 1.0.4。

## 變更摘要

- `src/index.ts`：
  - 移除 5 個 Section，回歸單一 `noteAi` 區塊。
  - 新增可見欄位 `aiApiKeyEditor`（API Key，secure）；原 4 個 key 設定改為 `public: false` 作為各 Provider 的內部獨立儲存位（既有已填值保留）。
  - `settings.onChange` 雙向同步：
    - Provider 切換 → 載入對應 slot 金鑰至編輯欄（防迴圈旗標 `syncingEditor`）。
    - 編輯欄變更 → 存回當前 Provider 的 slot（值相同時 no-op，防延遲 echo 誤寫）。
    - Provider 與編輯欄同 batch 變更 → 編輯值歸屬前一個 Provider（`lastKnownProvider` 追蹤）後再載入新金鑰，避免跨 Provider 誤存。
  - `onStart` 初始化同步一次（載入當前 Provider 金鑰至編輯欄）。
  - `resolveLLMConfig()` 一律讀取 slot（非編輯欄）作為唯一事實來源。
  - 缺金鑰錯誤訊息依 Provider 指引：「於 Provider『○○』狀態下的 API Key 欄位填入金鑰」。
- `AGENTS.md`：新增「版號一致性（硬性規定）」條款 — 遞增版號後必須重新 `npm run dist`，以 `tar -xOf publish/*.jpl manifest.json` 檢查產物版號後才可 commit；驗證記錄須含產物版號檢查項目。

# 驗證記錄 — v1.0.14

- **日期**：2026-09-07
- **版號**：1.0.14（package.json + src/manifest.json + publish/*.jpl 內嵌版號，三者一致）

## 需求描述

1. **深度查因**：按【生成】後視窗直接關閉、零訊息（Joplin 3.6.14）。
2. 刪除「套用所選 Provider 的 API 端點」功能。
3. 連線測試改為發送「你是誰」，並在 UI 顯示 AI 完整回覆。

## 根因分析（原始碼證據鏈）

- Joplin 桌面版外掛執行於**隱藏的 Electron BrowserWindow**（`PluginRunner.ts`：`newBrowserWindow({ show: false })`）
- 外掛宿主環境**未定義 `alert`**（`plugin_index.js` 僅注入 `joplin` proxy/IPC/console）→ `alert()` 落到 Chromium 原生 `window.alert`，對話框掛在隱藏視窗上 → **完全不可見**（且同步呼叫可能阻塞外掛宿主）
- 本外掛所有錯誤處理依賴 `alert()`（v1.0.3 起的潛藏缺陷）→ 任何例外（最可能：當前 Provider 的 API Key 落在錯誤 slot／缺模型名，`resolveLLMConfig()` 拋例外）都變成「無聲消失」
- 使用者診斷佐證：console 無第二次 `setHtml`（未達處理中畫面）、連線測試同機制健康（reopen 機制無問題）、key「已填寫」但可能非當前 Provider slot

## 變更摘要

- `src/notify.ts`（新增）：`showErrorBox()` / `showNoticeBox()` — 使用 `joplin.views.dialogs.showMessageBox()`（主視窗原生訊息框，永遠可見）
- `src/magicWand.ts`：
  - `resolveConfig()` 失敗 → **對話框內錯誤畫面 + [關閉]**（`showProcessingError`，不再 alert）
  - `!input.formData` 靜默 return → 改為 `showNoticeBox` 提示（表單資料缺失）
  - 其餘 alert（請先選擇筆記／輸入為空／外層 catch）→ notify 通道
- `src/connectionTest.ts`：
  - 測試提示詞 → 「你是誰」；`maxTokens` 64 → 512
  - 成功橫幅顯示 **AI 完整回覆**（2000 字顯示上限 +「…（已截斷）」）；提示文字同步更新
  - 外層 catch alert → showErrorBox
- `src/index.ts`：
  - **刪除** `COMMAND_APPLY_ENDPOINT`、`applyEndpoint()`、指令註冊 + Tools 選單項目；`SETTING_BASE_URL` 描述移除「套用端點」字樣（Provider 切換的自動端點載入不受影響）
  - processNote / noteAiChat 所有 alert → notify 通道

# 驗證記錄 — v1.0.12

- **日期**：2026-09-07
- **版號**：1.0.12（package.json + src/manifest.json + publish/*.jpl 內嵌版號，三者一致）

## 需求描述

按【生成】後視窗關閉，LLM 處理期間（數秒到數分數分鐘）僅短暫 Toast，使用者感覺視窗「消失」。
**根因**：Joplin `dialogs.open()` 行為 — 按鈕點擊後對話框自動關閉並回傳結果，原流程在 LLM 呼叫期間視窗處於關閉狀態。

**已查證的 Joplin 原始碼（3.6.14）支持原地更新**：
- `WebviewController.setOpen()`：重複 `open()` 安全 — 舊 pending promise 被 `resolve(null)`，新 pending 接手
- `setHtml`/`setButtons` → `PLUGIN_VIEW_PROP_SET` store dispatch → `PluginDialogs.tsx` / `UserWebviewDialog` 由 props 驅動即時重繪
- `setButtons([])` 時 `UserWebviewDialog` 以空陣列渲染（無預設按鈕注入）

## 變更摘要

- `src/magicWand.ts` 流程改為三段連續視窗（全程保持開啟）：
  1. **Phase 1**（不變）：輸入表單 → 按「生成」
  2. **Phase 1.5 處理中（新增）**：立即重開視窗顯示 spinner「AI 處理中，請稍候…（模型：{model}）」+ [取消]；以 `void open(handle)` 掛住 pending（不 await，避免擋住 LLM 呼叫）
  3. **Phase 2**：LLM 完成 → **原地換頁**為「輸入內容 + 生成結果」預覽（不關窗）→ 寫入按鈕照舊
  - [取消] 於處理中階段僅隱藏視窗（LLM 繼續執行，完成後結果照常出現）
- 錯誤處理重構：LLM 失敗/空回覆 → `showProcessingError()` 於對話框內顯示錯誤畫面（escape 後的訊息 + [關閉] 按鈕），不再卡在 spinner；非視窗階段錯誤維持 alert
- 移除「AI 處理中」Toast（畫面已呈現進度）
